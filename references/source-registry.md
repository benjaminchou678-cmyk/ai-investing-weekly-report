# 来源与关注对象

完整周报使用同目录的 `source-registry.json` 作为机器可读清单。本文件说明选择原则；不要在 Markdown 和 JSON 中维护两套不一致的 required 列表。

## 优先级

- `C1`：每周必查的公司、监管与资本市场一手来源；
- `C2`：出现动态时优先检查；
- `C3`：按赛道和本周信号选择性扫描。

来源角色分为：

- `primary_company`：公司新闻、IR、财报、产品与工程文档；
- `primary_regulatory`：监管申报、交易所公告、政府文件；
- `independent_media`：具有编辑核验能力的媒体；
- `market_context`：市场预期、交易、估值和资本数据；
- `builder` / `research` / `aggregator`：发现与技术补充。

来源角色不直接决定事实真假；同一利益相关方旗下来源使用相同 `independence_group`。

## 覆盖原则

- 上市公司优先检查 IR、财报、监管申报和电话会原文；
- 非上市公司优先检查公司公告、客户/合同证据和独立报道；
- 融资、估值和用户量尽量找到原始披露，并注明是否得到独立验证；
- 技术媒体、榜单、Newsletter、Product Hunt 和聚合源主要用于发现；
- 证券层结论需要价格、估值和市场预期，缺失时只给研究优先级。

## 维护

每季度复核一次机器清单：URL 可用性、公司优先级、来源角色和 required 状态。临时新增来源记录在当期 coverage 中，并在多期稳定使用后再进入注册表。

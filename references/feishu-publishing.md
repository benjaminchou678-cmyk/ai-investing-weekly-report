# 飞书发布流程

仅在用户明确要求创建、更新或推送飞书周报文档、卡片或结构化沉淀时读取。

## 授权边界

- 本地生成 Markdown 不等于授权发布飞书；
- 草稿、视觉和 QA 未确认前不推送；
- 用户只要求创建文档时，不自动发送群卡片；
- 用户只要求修改局部内容时，不覆盖整个文档。

## 发布顺序

1. 确认最终 Markdown 和 QA 状态；
2. 如需视觉，先按 [视觉工作流](visual-workflow.md) 生成并验收；
3. 创建或更新飞书详细版文档；
4. 将趋势图分别插入对应趋势段落之后；
5. 创建或更新结构化沉淀；
6. 只有用户要求推送时才生成并发送 Newsrun 卡片；
7. 回读文档和卡片，确认顺序、链接和内容。

## 图片插入

- 趋势 1/2/3 图片分别跟在对应趋势的正文和来源之后；
- 不把三张图集中堆在章节末尾；
- 插图时保留原有标题、数据、判断和来源；
- 使用等比例 16:9 显示尺寸，例如 960×540；
- 局部更新不得使用会覆盖整篇内容的操作。

## 元数据

将插图结果写入 `feishu-detailed-report-metadata.json`：

```json
{
  "document_id": "...",
  "revision": 1,
  "images": [
    {
      "trend_index": 1,
      "local_file": "trend-1.png",
      "source_size": "1920x1080",
      "display_size": "960x540",
      "block_id": "...",
      "file_token": "..."
    }
  ]
}
```

插图后局部回读，核对 block 顺序、尺寸、链接、block ID 和 file token。

## 结构化沉淀

结构化文档或表格至少保留：日期、编号、板块、标题、信号等级、事实核验、关联公司、关联赛道、来源、原文 URL、摘要和是否推送。

不得因为结构化输出而丢失证据状态和首个原始链接。

## 发布完成条件

- 最终文档标题与日期正确；
- 三大趋势、正文板块和 QA 报告顺序正确；
- 图片位于对应趋势下方；
- 所有外链可点击；
- 元数据已保存并可回读；
- 卡片只在用户授权时推送；
- 发布失败时保留本地最终版并报告失败位置，不重复创建重复文档。

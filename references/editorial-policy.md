# 编辑与投资判断标准

本文件用于从候选池选择周报核心事件、形成周度关键判断并更新投资假设。

## S/A/B/noise 编辑评级

等级由 Agent 阅读原始材料、完成事实核验并判断经营/产业影响后给出；脚本不得从关键词、金额、公司名、来源数或旧百分制字段自动换算。每个等级必须同时写 `signal_reason`：

| 等级 | 标准 |
|---|---|
| S | 已核验且高材料性，可能改变行业格局、公司核心经营假设或资源配置 |
| A | 已核验，对客户、开发者、预算、成本、分发或公司经营产生直接影响 |
| B | 有明确意义但影响范围有限、后续影响仍待验证，适合作为观察项 |
| noise | 无实质进展、重复营销、重复信息，或在完成复核后仍无法形成可用事实；不进入正文 |
| unrated | Agent 尚未完成评级；进入 `human_review_queue`，不得自动当作 noise |

信号等级与证据状态分开记录：事件可以重要但待核验，此时先进入复核队列，而不是靠重要性进入正文。评级只决定编辑优先级，不替代 claim 来源映射、反方证据和投资判断。

## 判断（thesis）构建规则

每条可发布判断必须包含：

- `statement`：Agent 基于已审核证据写出的具体、可证伪主张；脚本不得生成模板句或覆盖定稿；
- `structural_change`：本周发生的结构性变化；
- `key_evidence`：1–4 个已审核事件；
- `why_it_matters`、`investment_readthrough`、`counter_evidence`、`falsification_conditions`、`confidence`。

判断是否发布由 Agent 根据事件材料性、事实核验、推理链和反证综合决定，不设机械事件数量门槛：

- 一件 S/A 级高材料性事件可以主导周度判断；
- 多事件判断必须解释它们为何共同支持同一变化，不得机械拼接；
- 日期、身份、来源或核心事实待复核的事件不得作为判断证据；
- `key_evidence` 只引用权威 JSON 中已审核的 `core_events`、`watchlist` 或 `editorial_candidate_pool` 事件。

判断可以跨栏目，数量动态 0–3，**不凑数**。脚本不生成模板判断；Agent 把最终主张、反证和推翻条件直接写入权威 JSON。

## 三层判断

不要把“行业重要”“公司经营优秀”和“证券值得买”混为一谈：

1. **行业层**：市场、技术或监管约束是否发生结构变化？
2. **公司层**：收入质量、成本、渠道、壁垒、资本配置或组织执行是否变化？
3. **证券层**：变化是否尚未被估值和市场预期反映？只有用户明确要求证券分析时才进入此层。

默认周报停留在前两层，并给出研究优先级。

## 入选标准

核心事件至少满足一项，并具有可回溯证据：

- 改变收入、定价、付费或留存；
- 改变利润率、推理成本、交付成本或资本开支；
- 改变渠道、获客、工作流入口或竞争壁垒；
- 改变组织执行、关键人才、数据供给或供应链；
- 形成未来 1–12 周可验证催化剂；
- 强化、削弱或推翻既有投资假设。

融资、产品发布和合作本身不是经营证据。功能小更新、重复转载、营销软文、无证据传闻和一般教程默认删除。

## 投资假设

每条入选事件绑定一条明确、可被证伪的假设，记录：

- `statement`：结构性判断；
- `impact`：new / strengthen / weaken / invalidate / neutral；
- `rationale`：本周新增证据；
- `counter_evidence`：反方证据或关键缺口；
- `catalyst`：下一步验证事件；
- `time_horizon`：1–4周、1季度、1年以上。

## 判断数量与板块（动态，非配额）

可发布产业判断为 **0–3 条**：正常周建议 1–3 条；证据不足时允许 0 条，并明确写"本周未形成达到证据门槛的产业判断"。**不为凑满三条而降低证据标准。**

产品与模型、组织与人事、投融资，以及政策、算力、安全、人才等只作为**检索标签、事件分类标签、来源覆盖审计维度和事件关联分析维度**，不再是前台强制栏目，也不要求每个板块都形成判断。一条判断可关联多个板块，用 `related_boards` 标注。

关键判断回答"本周最重要的变化是什么，以及它接下来可能改变什么"。它不同于趋势：

- 允许由一件 S/A 级高材料性事件主导，不要求为了形式凑足两个事件；
- 如果使用一组事件，应说明它们为何共同指向同一变化，不能把无关新闻拼成主题；
- 一手事件可以由公司原始材料确认，但关键数字和争议性 claim 应尽量获得独立来源；
- 每条判断必须写清：主张、核心变化、关键证据、为什么重要、Investment Readthrough、反方证据、推翻条件、置信度、关联板块；
- 判断置信度使用 `low / medium / high`。高置信度要求关键事实已被一手材料与至少一个独立来源或两个相互独立来源支持；中置信度表示核心事实较可靠但影响链仍待验证；低置信度表示事件或影响仍存在重要缺口，正文必须避免确定性表述。
- `independence_status=unknown` 的证据不能通过独立证据门；不得重复计算同集团、转载或同一原始来源。

单周判断不得直接称为长期趋势。连续 2–3 周出现方向一致、可独立验证的后续证据后，才可在月报、季度复盘或跨周验证中升级为趋势。以后每期必须回看上一期判断，并标记"已验证、部分验证、未验证、被推翻"。

## 公司研究优先级

“研究优先级高”意味着本周出现了高材料性且可验证的新信息，不意味着推荐买入。建议定性说明经营证据、分发、资本效率、壁垒、催化剂、独立性与风险；如需数值评分，必须另建与证券研究目标匹配的明确模型，不能复用事件 S/A/B/noise 等级。

- 经营证据；
- 分发与客户控制力；
- 单位经济与资本效率；
- 数据、工作流、生态或供应链壁垒；
- 催化剂可验证性；
- 证据独立性；
- 主要风险与反证。

缺少估值和市场预期时不得把研究优先级转译为证券吸引力。

## 事实与判断分层

- 事实：原始来源直接支持；
- 利益相关方披露：公司、创始人、投资方或客户自述；
- 独立验证：与利益相关方独立的来源支持同一 claim；
- 媒体转述：尚未找到原始材料；
- 编辑判断：写清底层变量、推理链和反证；
- 待核验：只进入观察项，不写成确定事实。

## 事件分类标签与候选池分层

产品与模型、组织与人事、投融资是后台分类标签，用于检索、审计与事件关联，不构成前台栏目配额。自动化负责排序，人保留最终编辑判断权。

**候选池必须分层保留，不得在进入人工判断前过早删除：**

```text
完整发现池
→ standardized_candidates
→ event_clusters
→ ranked_events（保留全部有效事件；按 Agent 的 S/A/B/noise 稳定排序）
→ 先分离 human_review_queue（日期/身份/独立性/事实/评级不完整）
   ├── S/A  core_events（正文建议 5–7）
   ├── B 或需继续验证的 A  watchlist（正文建议 3–5）
   ├── 正文额度外 S/A/B  editorial_candidate_pool（完整保留）
   ├── noise  appendix_events（Source Pool）
   └── 明确排除 → excluded_events（保留完整记录和 reason）
```

每个 `input_event_id` 必须恰好出现在一个候选层。脚本不得静默丢弃、截断或用低等级事件补齐正文额度。

- `产品与模型`：国内外科技大厂重要产品/模型发布，及足以改变能力边界、成本、定价、分发或开发者生态的版本。普通功能更新、只改版本号、缺方法说明的 benchmark 刷榜和营销预告默认删除。
- `组织与人事`：可能改变资源配置、产品路线、研究能力或组织执行的任命、离职、加入、创业和重大重组。普通招聘、常规晋升、无可靠来源的传闻和与 AI 主线无关的人事默认删除。
- `投融资`：有行业或公司阶段意义的融资、战略投资、并购及 IPO/募资。至少核验主体、轮次、金额是否披露、主要投资方和日期；无可靠依据时写"未披露"。小额无战略意义、单一传闻、旧融资重复和纯募资宣传默认删除。

核心事件建议 5–7，**少于 5 但明确披露证据不足可 WARN**，不得静默用低等级事件补足；Watchlist 建议 3–5；候选池数量不受正文 5–7 限制。信息稀疏时可少于下限，但必须说明本周无更多达到标准的事件。同一事件只进入一个正文层。

政策、安全、客户采用、基础设施、论文和观点保留在候选池，用于关键判断、反方证据和投资假设。

对于上市公司优先提取收入、利润率、资本开支、指引、订单、客户与资本配置。对于初创公司优先提取付费方、合同、重复购买、留存、毛利、现金流、runway 和交付风险。无法获得时明确缺口，不用融资额替代。
